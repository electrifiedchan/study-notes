Q1 · Applications of Cryptographic Hash Functions

PYQ ×0* — rare as a full 10-marker
Definition. A cryptographic hash function H takes a variable-length message M and produces a fixed-length output h = H(M), called the hash / message digest / fingerprint. It must be one-way (preimage resistant), second-preimage resistant, and collision resistant.

Interactive — the avalanche effect

Type a message. A tiny change (one character) flips roughly half the output bits — this is why hashes detect tampering. (Demo digest, not real SHA.)

Q1Explain the applications of cryptographic hash functions. (10 marks)
Intro (write 2–3 lines): A cryptographic hash function H takes a message M of any length and produces a fixed-size output h = H(M) called the message digest. It is the most versatile cryptographic algorithm, used in a wide variety of security applications and Internet protocols. Its major applications are the following.

1. Message authentication

Used to verify the integrity of a message — to assure the receiver the data was not altered, inserted, deleted or replayed in transit.

  • Sender computes a hash H(M) (the message digest) and sends it along with M.
  • Receiver recomputes the hash of the received message and compares it with the received digest.
  • Match → message is authentic; mismatch → message was tampered with, so reject it.

But the digest itself must be protected — otherwise an attacker (Darth) can change M and recompute the hash, fooling the receiver (man-in-the-middle):

Ways hash codes are used for message authentication:

(a) E(K, [M ∥ H(M)]) — the message and hash are concatenated and encrypted with a shared secret key. Provides authentication and confidentiality.

(b) M ∥ E(K, H(M)) — only the hash is encrypted with the shared key. Gives authentication with less processing (no confidentiality).

(c) M ∥ H(M ∥ S) — no encryption; A and B share a secret value S. A sends the hash of M ∥ S; B recomputes with S. Since S is never sent, an attacker cannot forge it. This is the basis of a MAC / HMAC.

(d) E(K, [M ∥ H(M ∥ S)]) — confidentiality can be added by also encrypting the message and secret-keyed hash.

2. Digital signatures

An authentication technique that also provides non-repudiation (sender cannot later deny sending). It uses public-key cryptography.

(a) The sender computes H(M) and encrypts the digest with its private key PRa — this is the signature. Any receiver verifies it with the sender's public key PUa: decrypt the signature, recompute H(M), and compare. A match proves integrity, authentication and non-repudiation at once. Only the small digest is signed, so it is fast.

(b) If both confidentiality and a signature are needed, the message plus the signed hash are encrypted with a shared symmetric key K: E(K, [M ∥ E(PRa, H(M))]).

3. One-way password file

  • The OS stores only H(password), never the plain password; at login it hashes the input and compares.
  • Preimage resistance keeps passwords safe even if the file leaks; a random salt defeats rainbow-table attacks (UNIX/Linux).

4. Intrusion detection & virus detection

  • Store each critical file's hash H(F) in a secure place, then periodically recompute and compare.
  • A mismatch signals tampering (virus/backdoor); second-preimage resistance stops an attacker altering a file without changing its hash.

5. Pseudorandom function (PRF) / pseudorandom number generator (PRNG)

  • A hash output is uniform and unpredictable, so hashing a secret seed with a counter yields a stream of pseudorandom bits.
  • Used to generate keys, IVs and nonces (key-derivation functions and PRNGs).

Required properties (state these for the extra marks)

PropertyMeaning
Preimage resistanceGiven h, infeasible to find M with H(M)=h (one-way)
Second-preimage resistanceGiven M, infeasible to find M'≠M with same hash
Collision resistanceInfeasible to find any pair M, M' with same hash
"A cryptographic hash function condenses an arbitrary message into a fixed-size fingerprint. Its one-wayness and collision resistance make it the workhorse behind message authentication, digital signatures, secure password storage, intrusion/virus detection, and pseudorandom generation."

Conclusion: A cryptographic hash function condenses an arbitrary-length message into a fixed-size fingerprint whose one-wayness, second-preimage resistance and collision resistance make it indispensable. The same primitive is reused across all five applications — integrity and authentication come from comparing a freshly recomputed digest against a protected one, while signatures, secure password storage, intrusion/virus detection and pseudorandom generation each exploit a different combination of these properties. This makes the hash function one of the true workhorses of modern cryptography.

Q2 · X.509 Certificate

Definition. X.509 is an ITU-T standard (part of the X.500 series) that defines the format of a public-key certificate — a data structure that binds a public key to its owner's identity, vouched for by a trusted Certification Authority (CA) that digitally signs it. It underpins SSL/TLS, S/MIME and IPSec.

Q2Explain the format of an X.509 certificate and how it is verified. (10 marks)

Certificate format (the fields)

An X.509 certificate contains, in order:

  1. Version — v1, v2 or v3 (v3 supports extensions).
  2. Serial number — unique integer within the issuing CA.
  3. Signature algorithm identifier — algorithm + parameters used to sign the certificate.
  4. Issuer name — X.500 name of the CA.
  5. Period of validity — not-before and not-after dates.
  6. Subject name — name of the user the certificate belongs to.
  7. Subject's public-key information — the public key, algorithm and parameters.
  8. Issuer unique identifier / Subject unique identifier (v2+, optional).
  9. Extensions (v3, optional) — e.g. key usage, alternative names.
  10. Signature — the CA's signature over all the above fields.
Mnemonic (same order as the 10 fields): “Very Smart Spies Issue Passports, So People Use Extra Signatures.”
Very=Version, Smart=Serial, Spies=Signature-algorithm, Issue=Issuer, Passports=Period of validity, So=Subject, People=Public-key info, Use=Unique identifiers, Extra=Extensions, Signatures=CA Signature. (Note the two S's: Spies = algorithm id at the top, Signatures = the real CA signature at the bottom.)

Notation

A certificate for user A issued by CA is written:

CA<<A>> = CA { V, SN, AI, CA, T_A, A, Ap }

where { } means the CA signs (hashes then private-key-encrypts) the fields: version V, serial SN, algorithm AI, issuer CA, validity T_A, subject A, and A's public key Ap.

How a certificate is created & verified

  1. User A generates a key pair and sends its public key to the CA (proving identity out-of-band).
  2. The CA forms the certificate fields, hashes them, and encrypts the hash with the CA's private key — this signature is appended.
  3. Any user B who trusts the CA and holds the CA's public key can verify: recompute the hash of the fields, decrypt the signature with the CA's public key, and compare. A match proves the certificate is authentic and untampered.
Draw the stacked-box certificate: one box per field, top to bottom, with the signature as a filled band at the bottom. Add a small side note "CA hashes + signs with private key". A second sketch of verification (recompute hash vs decrypt signature) earns the diagram marks.

Certificate revocation

A certificate may be revoked before expiry (key compromised, user leaves, CA key compromised). CAs publish a Certificate Revocation List (CRL), signed and timestamped, listing revoked serial numbers.

"X.509 solves the trust problem of raw public keys: instead of trusting a key directly, you trust a CA, and the CA vouches for the key by signing a certificate. Verification is just recomputing a hash and checking the CA's signature."

Takeaway: a certificate = identity + public key + CA's signature. Trust flows from the CA's public key, which everyone is assumed to hold securely.

Q3 · Public-Key Infrastructure (PKI) Model

PYQ ×1 — occasional
Definition. A PKI is the set of hardware, software, people, policies and procedures needed to create, manage, distribute, use, store and revoke digital certificates based on public-key cryptography. The IETF model is PKIX.
Q3Explain the PKIX model / architecture with a diagram. (10 marks)

PKIX components

  • End Entity (EE) — the user, device or service that owns a certificate (the certificate subject).
  • Certification Authority (CA) — issues and signs certificates and CRLs; the root of trust.
  • Registration Authority (RA) — optional; verifies the identity of certificate applicants on the CA's behalf (offloads the CA).
  • CRL Issuer — optional component to which a CA delegates publishing of revocation lists.
  • Repository — a database / directory (e.g. LDAP) that stores and distributes certificates and CRLs.

PKIX management functions

  • Registration — the user first identifies itself to the CA (directly or via an RA); begins PKI enrolment through online/offline mutual authentication, and the user receives shared secret keys for future authentication.
  • Initialization — installs the required key information in the client system, including the trusted CA's public key so the client can verify certificates.
  • Certification — the CA issues a certificate for the user's public key and returns it to the user or stores it in the repository.
  • Key-pair recovery — allows lost encryption/decryption keys to be restored from an authorised backup facility (usually the CA).
  • Key-pair update — key pairs are replaced periodically and new certificates issued; required when a certificate expires or is revoked.
  • Revocation request — an authorised person asks the CA to revoke a certificate (reasons: private-key compromise, affiliation change, name change).
  • Cross-certification — one CA issues a cross-certificate to another CA, containing that CA's public key used for issuing certificates.

PKIX management protocols

  • Certificate Management Protocol (CMP) — defines the protocol exchanges for all the management functions above; flexible, supporting different technical and business needs.
  • Certificate Management over CMS (CMC) — builds on existing certificate-management work; used to obtain and manage X.509 certificates in a PKI.
Draw four boxes: End Entity (left), RA + CA + CRL issuer stacked (middle), Repository (right). Label the arrows: register → RA, certify → CA, publish → repository, revoke → CRL. Keep arrows one-directional and labelled.
"PKIX takes the single CA idea of X.509 and turns it into a full operational system — adding registration authorities, repositories and revocation machinery so that certificates can be issued, published, validated and revoked at scale."

Takeaway: X.509 defines the certificate; PKI/PKIX defines the whole lifecycle and the entities that manage it.

Q4 · Simple Secret Key Distribution

PYQ ×3 — frequent
Idea (Merkle). Use public-key crypto once, only to distribute a one-time symmetric session key — then throw the public keys away. Simple and needs no prior keys, but it is fatally exposed to a man-in-the-middle.
Q4Explain simple secret key distribution using public keys, its man-in-the-middle weakness, and its pros/cons. (10 marks)

The protocol (Merkle, 1979)

  1. A generates a public/private key pair {PUa, PRa} and transmits PUa || ID_A to B.
  2. B generates a secret session key Ks, encrypts it with A's public key, and sends E(PUa, Ks) to A.
  3. A computes D(PRa, E(PUa, Ks)) to recover Ks. Now both A and B share Ks.
  4. A discards PUa, PRa and B discards PUa. The public keys were temporary, so no long-term storage or prior distribution is needed.

The man-in-the-middle (MITM) attack

Because the public key is sent unauthenticated, an attacker Darth can sit between A and B:

  1. A sends PUa || ID_A; Darth intercepts and sends PUd || ID_A to B instead.
  2. B generates Ks, sends E(PUd, Ks) (thinking it's A's key). Darth decrypts to get Ks.
  3. Darth re-encrypts E(PUa, Ks) and forwards to A. A recovers Ks.
  4. Now A, B and Darth all know Ks. Darth transparently eavesdrops and modifies traffic; neither party detects him.
Draw A ---> B with the two labelled arrows for the safe case. For the attack, put Darth in the middle and show four arrows (A→D, D→B, B→D, D→A) with the swapped keys PUd/PUa labelled. This attack diagram is where the marks are.

Advantages & disadvantages

AdvantagesDisadvantages
No keys need to exist beforehandNo authentication of the public keys
Public keys are temporary — nothing to storeCompletely broken by a man-in-the-middle
Simple, few messagesVulnerable to eavesdropping if attacker is active
"The scheme is elegant — public keys used once, then discarded — but its silence on authentication is fatal: without confirming whose public key you received, a man-in-the-middle simply substitutes his own and shares the session key with both sides undetected."

Takeaway: confidentiality without authentication is not security. The fix is to authenticate the public keys — e.g. via certificates (Q2) or a distribution scheme with confidentiality + authentication.
